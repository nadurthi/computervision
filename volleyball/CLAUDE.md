# volleyball

Broadcast-camera volleyball analysis (perceptionstack.dev, Applications › volleyball parts 1 and 2).

- Code: `vb/` (one module per stage; `vb/pipeline.py` ties them together). Tests: `python -m pytest -q tests`.
- Notebooks are generated by `scripts/build_notebooks.py`: edit that file, then run it; never hand-edit the `.ipynb`.
- Config: `configs/default.yaml` → `vb.config.load_config`. Court seed points are per clip (notebook 01).
- Data lives in S3, bucket `$VB_BUCKET` (`vb-data-<account-id>`): `datasets/<name>/raw/` + `MANIFEST.json`,
  `clips/`, `labels/`, `models/`, `runs/<run>/`. Public datasets: `scripts/datasets_to_s3.py --list`.
- Licences: check `commercial_ok` in a dataset's `MANIFEST.json` before training anything meant for a product
  (SportsMOT and the Koshkina jersey weights/crops are non-commercial).
- Runs on a SageMaker Studio GPU space (A10G or L4) with the execution role; no AWS keys in code or notebooks.
- Determinism: never mix NVDEC and CPU decoding in one run; TensorRT engines are built from the pinned timing
  caches in `models/` (`vb/trt.py`).
- Results that go on the blog: `runs/<run>/summary.json` and `python scripts/eval_rule_on_dvw.py`.
