Multi-view stereo: classical vs learned, and why N views beat two under occlusion

Give a computer N photographs with known intrinsics and extrinsics and ask for a depth map. With two views this is stereo, and it has a hard floor: every pixel the second camera cannot see has no correspondence, so its depth can only be guessed. Multi-view stereo (MVS) attacks that floor directly, because a point hidden from one camera is usually visible from another. This page derives the geometry and the algorithms, from plane sweeping and PatchMatch to learned cost volumes, and sets up a benchmark that measures the occlusion effect pixel by pixel: same images, same cameras, same ground truth, two-view stereo vs. N-view MVS, classical vs. learned.

Code (benchmark, AWS GPU runner, dataset and model setup): nadurthi/computervision · multi-view-stereo/. Background: camera model · stereo & disparity · structure from motion. A short glossary-level intro is Activeloop's MVS entry; this page goes into the math and the code.

1 · The calibrated N-view setting

We have a reference image $I_0$ and source images $I_1,\dots,I_{N-1}$. Camera $i$ has intrinsics $K_i$ and a world-to-camera extrinsic $[R_i\,|\,\mathbf t_i]$, so a world point $\mathbf X$ projects to

$$\tilde{\mathbf x}_i \simeq K_i\,(R_i\mathbf X+\mathbf t_i),\qquad \mathbf x_i=\pi(\tilde{\mathbf x}_i)=\big(\tilde x/\tilde z,\ \tilde y/\tilde z\big).$$

The goal is the depth map $D_0(\mathbf p)$ of the reference: for each pixel $\mathbf p$, the distance $d$ along the optical axis such that $\mathbf X=d\,K_0^{-1}\tilde{\mathbf p}$ lies on the surface. With the relative pose $T_{i0}=[R\,|\,\mathbf t]$ taking reference-camera coordinates to camera $i$, a depth hypothesis $d$ at $\mathbf p$ maps to

$$\mathbf x_i(\mathbf p,d)=\pi\!\big(K_i(d\,R\,K_0^{-1}\tilde{\mathbf p}+\mathbf t)\big)=\pi\!\big(d\,\mathbf a(\mathbf p)+\mathbf b\big),\qquad \mathbf a=K_iRK_0^{-1}\tilde{\mathbf p},\ \ \mathbf b=K_i\mathbf t .$$

As $d$ varies, $\mathbf x_i$ traces the epipolar line of $\mathbf p$ in image $i$. Depth estimation is the search along those N−1 lines for the $d$ at which all images agree. Two-view rectified stereo is the special case where the line is a scanline and $\mathbf x_1=\mathbf p-(fB/d,\,0)$, i.e. disparity $\delta=fB/d$.

Precision vs baseline. Differentiating $d=fB/\delta$ gives the classic error propagation

$$\sigma_d\approx\frac{d^2}{fB}\,\sigma_\delta ,$$

so depth error grows with the square of distance and shrinks with baseline $B$. A wide baseline is precise but sees the scene from a more different angle (more occlusion, more appearance change). MVS can have both: a near source for robust matching and a far source for precision, in the same cost.

2 · The plane-induced homography

Almost every MVS algorithm, classical or learned, evaluates hypotheses of the form "the surface at $\mathbf p$ is locally the plane $\mathbf n^\top\mathbf X=\rho$" (in reference-camera coordinates). For points on that plane $\mathbf n^\top\mathbf X/\rho=1$, so

$$\mathbf X_i=R\mathbf X+\mathbf t=\Big(R+\frac{\mathbf t\,\mathbf n^\top}{\rho}\Big)\mathbf X \quad\Longrightarrow\quad \tilde{\mathbf x}_i\simeq H\,\tilde{\mathbf x}_0,\qquad H=K_i\Big(R+\frac{\mathbf t\,\mathbf n^\top}{\rho}\Big)K_0^{-1}.$$
  • Fronto-parallel planes ($\mathbf n=[0,0,1]^\top$, $\rho=d$) give one homography per depth for the whole image. Warping each source with $H(d)$ for $d=d_1,\dots,d_D$ is the plane sweep; stacking the warped images (or features) is the cost volume.
  • Slanted planes ($\mathbf n$ per pixel, $\rho=\mathbf n^\top\mathbf X_\mathbf p=d\,\mathbf n^\top K_0^{-1}\tilde{\mathbf p}$) give one homography per pixel. That is what lets PatchMatch compare whole windows on tilted surfaces without the fronto-parallel bias.

Learned MVS uses exactly the same $H$, applied to CNN feature maps instead of pixels. MVSNet calls it differentiable homography warping: bilinear sampling through $H$ is differentiable, so the network can be trained end to end through the geometry.

3 · Photo-consistency

For a window $W(\mathbf p)$ and a hypothesis $\theta$ (a depth, or a plane), compare the reference window with the warped source window. The workhorse is zero-mean normalized cross-correlation,

$$\mathrm{ZNCC}_i(\mathbf p,\theta)=\frac{\sum_{\mathbf q\in W}w_\mathbf q\,(I_0(\mathbf q)-\bar I_0)(I_i(H_\theta\mathbf q)-\bar I_i)}{\sqrt{\sum w_\mathbf q (I_0(\mathbf q)-\bar I_0)^2\,\sum w_\mathbf q (I_i(H_\theta\mathbf q)-\bar I_i)^2}},\qquad c_i=1-\mathrm{ZNCC}_i\in[0,2],$$

invariant to gain and offset between cameras. Gipuma and COLMAP use a bilateral weight $w_\mathbf q=\exp(-|I_0(\mathbf q)-I_0(\mathbf p)|/\sigma_c-\|\mathbf q-\mathbf p\|/\sigma_s)$, so a window straddling a depth edge mostly listens to pixels with the centre's colour — a cheap guard against foreground fattening. Census and SAD are common in stereo; learned methods replace all of this with a learned similarity of feature vectors (dot product, group-wise correlation, or variance).

With N−1 sources there are N−1 costs per hypothesis. How to combine them is the central design decision for occlusion and is the subject of §6.

4 · Classical MVS

4.1 Plane sweep (Collins 1996; Gallup et al. 2007)

Sample $D$ depths uniformly in inverse depth (uniform in disparity, which is uniform in pixel motion), warp every source through $H(d_k)$, compute $c_i(\mathbf p,k)$ with ZNCC, aggregate across sources into $C(\mathbf p,k)$, and take the winner:

$$k^\star(\mathbf p)=\arg\min_k C(\mathbf p,k),\qquad \hat k=k^\star+\frac{C_{k^\star-1}-C_{k^\star+1}}{2\,(C_{k^\star-1}-2C_{k^\star}+C_{k^\star+1})}$$

(parabolic sub-plane refinement). Cost: $O(D\cdot N\cdot HW)$ warps — embarrassingly parallel, which is why it was the first real-time MVS on GPUs. Its weakness is the fronto-parallel window on slanted surfaces and the independent per-pixel decision in textureless regions.

4.2 Semi-global aggregation (Hirschmüller 2008)

Treat the cost volume as a data term and add a smoothness prior along 1-D paths $\mathbf r$ through the image:

$$L_\mathbf r(\mathbf p,k)=C(\mathbf p,k)+\min\Big(L_\mathbf r(\mathbf p-\mathbf r,k),\ L_\mathbf r(\mathbf p-\mathbf r,k\pm1)+P_1,\ \min_j L_\mathbf r(\mathbf p-\mathbf r,j)+P_2\Big)-\min_j L_\mathbf r(\mathbf p-\mathbf r,j),$$

sum over 4–8 directions, then winner-take-all. $P_1$ penalizes small depth changes (slanted surfaces), $P_2$ large jumps (edges). OpenCV's SGBM is this algorithm on a two-view disparity volume; in our code the same recurrence runs on the multi-view plane-sweep volume (planesweep_bestk_sgm).

4.3 PatchMatch MVS (Bleyer 2011; Gipuma 2015; COLMAP 2016; ACMH/ACMM/ACMP/ACMMP 2019–2022)

Instead of testing all depths at every pixel, PatchMatch exploits that neighbouring pixels usually lie on the same plane. Each pixel carries a plane $\theta_\mathbf p=(d_\mathbf p,\mathbf n_\mathbf p)$:

  1. Random initialization: $d$ uniform in inverse depth, $\mathbf n$ random facing the camera. Among millions of pixels a few guesses are close.
  2. Propagation: pixel $\mathbf p$ evaluates the planes of its neighbours $\mathbf q$, re-intersected with its own ray: $d'=\rho_\mathbf q/(\mathbf n_\mathbf q^\top K_0^{-1}\tilde{\mathbf p})$. A good plane spreads across a surface in a few sweeps. Gipuma made this GPU-friendly with a red/black checkerboard: half the pixels update in parallel from the other half; ACMH picks the best candidates from eight adaptive neighbourhood regions.
  3. Refinement: perturb $d$ and $\mathbf n$ with a shrinking radius; keep what lowers the cost.

The cost of a plane at $\mathbf p$ is the bilateral ZNCC of §3 through the per-pixel homography of §2, aggregated over sources with view selection. COLMAP models, per pixel and source, a hidden variable "source $i$ sees $\mathbf p$" and infers it jointly with depth and normal by generalized EM, so occluded sources get low weight. ACMH uses a cheaper multi-hypothesis vote: sources whose costs are low for many candidate planes are trusted. Our patchmatch implementation uses the simplest robust rule, the mean of the $K$ best source costs.

Geometric consistency. After a photometric pass, ACMM (and COLMAP's second pass) adds a term that checks the hypothesis against the source depth maps: project $\mathbf p$ with $d$ into source $i$, read $D_i$ there, project back, and penalize the reprojection error $\epsilon_i(\mathbf p)$,

$$c_i^\text{geo}(\mathbf p,\theta)=c_i^\text{photo}(\mathbf p,\theta)+\lambda\min\big(\epsilon_i(\mathbf p),\epsilon_{\max}\big).$$

ACMM runs this coarse-to-fine; ACMP adds a planar prior from a triangulation of confident points so that textureless walls are filled by the plane through their textured borders; ACMMP combines both. This is still the strongest family of classical MVS on ETH3D (§8).

4.4 Depth-map fusion

N depth maps become one point cloud by keeping a reference depth only where enough sources agree: the reprojection round trip lands within one pixel and the relative depth difference is below 1%. This filter removes most outliers, and also most remaining occlusion errors (an occluded estimate rarely agrees with the views that actually see the point). DTU and ETH3D score the fused cloud by accuracy (distance from reconstruction to GT), completeness (GT to reconstruction) and their mean or an F-score.

5 · Learned MVS

5.1 MVSNet (Yao et al., 2018) — the template

Extract features $F_i=\phi(I_i)$ at ¼ resolution with a shared CNN. Warp each source feature map with $H(d_k)$ to get $V_i(k)$, and build a cost volume with the variance metric, which is defined for any N:

$$\mathcal C(k)=\frac1N\sum_{i=0}^{N-1}\big(V_i(k)-\bar V(k)\big)^2,\qquad \bar V(k)=\frac1N\sum_i V_i(k).$$

A 3-D CNN regularizes $\mathcal C$ into a probability volume $P(k\mid\mathbf p)=\mathrm{softmax}_k(-\tilde{\mathcal C})$, and depth is the differentiable soft-argmin (expectation) $\hat d(\mathbf p)=\sum_k d_k\,P(k\mid\mathbf p)$, trained with an L1 loss against GT depth. The probability mass around $\hat d$ doubles as a confidence for filtering. Note that the variance treats every source alike: an occluded view adds variance at the right depth exactly like an occluded view adds ZNCC cost in the classical mean.

5.3 Learned two-view stereo, for comparison

The stereo networks in the benchmark work on rectified pairs. RAFT-Stereo (2021) builds an all-pairs correlation pyramid along the scanline and refines disparity with recurrent GRU updates; IGEV-Stereo (2023) adds a geometry-encoding volume from a small 3-D CNN to initialize and guide the GRU; FoundationStereo (2025) injects Depth Anything V2 features and is trained on a million synthetic pairs for zero-shot use; MonSter (2025) fuses a monocular depth branch with the stereo branch. The monocular priors are interesting for occlusion: they let a two-view network guess depth where there is no correspondence, which is different from measuring it.

6 · Occlusion: the two-view floor and what N views buy

Call a reference pixel occluded in source $i$ if a closer surface hides its 3-D point from camera $i$, and out of view if it projects outside image $i$. In either case no correspondence exists, and the matching cost at the true depth is just as uninformative as at any other depth. A two-view method can only fill such pixels from priors (smoothness, background extension, a monocular network). With GT depth for every view the labels are exact:

$$\ell_i(\mathbf p)=\begin{cases}\text{visible}&|z_i-D_i(\mathbf x_i)|\le\tau\,D_i(\mathbf x_i)\\ \text{occluded}&z_i\gt(1+\tau)\,D_i(\mathbf x_i)\\ \text{out of view}&\mathbf x_i\notin\Omega_i\end{cases}\qquad(\mathbf x_i,z_i)=\text{projection of }D_0(\mathbf p)\text{ into }i .$$

6.1 How much N helps

If the views around the reference occluded independently with probability $p$, the chance that no source sees a pixel would be $p^{N-1}$: with $p=0.15$, 15% unmatched pixels for stereo, 2.3% with three sources, 0.05% with five. They are not independent — an occluder casts its "shadow" away from each camera's baseline direction — and this is exactly why MVS benefits from sources on different sides of the reference. A pixel hidden from the camera to the right is usually seen by the camera to the left. The benchmark measures the real fractions: the rescued region (not visible to the stereo partner, visible to at least one other source) and the unseen region (visible to none).

6.2 Why the aggregation rule matters as much as N

Adding views only helps if occluded views are kept out of the decision. Consider a pixel visible in $m$ of $N-1$ sources. At the true depth the visible sources give low costs $c\approx c_\text{true}$ and the occluded ones give arbitrary, typically high costs $c\approx\bar c_\text{rand}$. The mean aggregation is

$$C_\text{mean}(d^\star)=\frac{m\,c_\text{true}+(N-1-m)\,\bar c_\text{rand}}{N-1},$$

so the true minimum gets shallower as more of the views are occluded, and a wrong depth where the occluder happens to match can win. The best-K rule of Kang, Szeliski & Chai (2001), $C_K=\frac1K\sum_{\text{K lowest}}c_i$, keeps only the most consistent sources: if $m\ge K$, the occluded views simply never enter the sum. COLMAP's per-pixel visibility inference, ACMH's voting, Vis-MVSNet's visibility weights and PatchmatchNet's pixel-wise view weights are all more refined versions of the same idea. The benchmark runs plane sweep with both the mean and best-K so the effect of the rule is isolated from everything else.

6.3 What stays hard

  • Unseen pixels. Points visible to no source: only priors help (and every method is scored on them anyway, so a network with a good monocular prior can win there).
  • Thin structures and depth edges. Windows straddle two surfaces; bilateral weights, small windows and slanted planes help.
  • Textureless and reflective surfaces. Not an occlusion problem, but often the dominant error; planar priors (ACMP) and learned features (MVSFormer, FoundationStereo) target it.

7.3 Protocol and metrics

  • For every reference view and $N\in\{2,3,5,10\}$, each MVS method gets the reference and its $N-1$ best sources. Source #1 is the stereo partner, so $N=2$ is exactly the two-view problem, and the stereo methods see the same pair.
  • Every prediction is resized (nearest) to one evaluation grid per dataset and scored against GT depth. A missing prediction counts as an error; density is reported separately.
  • Metrics: % of pixels within 1/2/4 mm (DTU) or 2/5/10 cm (ETH3D), inlier ratio $\max(\hat d/d,d/\hat d)\lt1.03$, AbsRel. Stereo: EPE and bad-τ / D1 on all, non-occluded and occluded pixels.
  • Regions, from GT depth of the reference and all sources: visible in partner · occluded in partner · outside partner · rescued (not visible in partner, visible in another source) · unseen (visible in none).
  • DTU point clouds: N=5 for every view, identical geometric-consistency fusion for all methods, scored with a faithful Python port of the official evaluation.

9.4 What the numbers say

  • Occlusion is the case for MVS, and it is large. On ETH3D, ACMMP gets 2.2% of the partner-invisible pixels right with two views, 26.7% with three, 44.8% with five and 66.2% with ten — a thirtyfold gain, while its all-pixel score goes 51.8 → 77.9. The occluded/outside pixels are exactly where the two-view floor of §6 sits; extra views lift that floor, as predicted. DTU shows the same shape at a smaller scale (5.1 → 27.5): the curve saturates by N = 5, probably because its cameras sit on one sphere cap, so a pixel hidden from the nearest source tends to be hidden from the next ones too.
  • Best classical ≈ best learned, in domain. On DTU the top five (ACMMP 65.1, PatchmatchNet 64.2, Vis-MVSNet 63.4, IterMVS 62.2 / 61.1) are within 4 points. The difference is cost: PatchmatchNet and IterMVS take 0.3 s per view, ACMMP 3.2 s and Vis-MVSNet 5.8 s.
  • Out of domain, training data decides. PatchmatchNet, trained on DTU, falls to 42.8 on ETH3D; IterMVS with BlendedMVS weights holds 66.2 (vs 61.7 with its DTU weights) at 0.16 s per view. ACMMP, with no training at all, stays on top (70.0). If you have to pick one fast network for unknown scenes, pick one trained on varied data.
  • A monocular prior fills what no view sees. MVSAnywhere is the only method that does well on unseen pixels (39.4% on ETH3D; everyone else ≤ 8%) and on partner-invisible pixels at N = 2 (38.4%): its depth prior guesses plausibly where matching cannot. It also has by far the lowest AbsRel (1.4% on ETH3D vs 47% for ACMMP, whose mean is dominated by a few gross outliers). The flip side is precision: on DTU's 2 mm threshold it is only 32.6. Robust and roughly right everywhere, vs very precise where there is texture.
  • The aggregation rule matters, and best-K alone is not enough. Taking the K best source costs per depth hypothesis (§6) is meant to ignore the occluded sources, but with no smoothing it also picks the best accidental match among more candidates: on DTU it scores below the plain mean (20.6 vs 28.7 at N = 5) and drops as N grows. Adding SGM regularisation fixes most of that (best-K + SGM beats the mean on ETH3D, 26.8 vs 18.2, and on DTU's partner-invisible pixels at N = 5). PatchMatch-style methods get the same benefit more cleanly through per-pixel view selection and propagation.
  • Engineering beats the textbook. Our ~250-line PatchMatch MVS (slanted planes, bilateral NCC, top-K view selection) reaches 52.7 on DTU — far above the plane sweeps, but 12 points below ACMMP, whose multi-scale geometric consistency and planar priors are the likely difference. On the partner-invisible pixels it needs N ≥ 5 before view selection has enough sources to choose from (2.7 → 17.7 from N = 3 to 5).

9.6 Sanity check on a synthetic scene (CPU)

Before any GPU time, scripts/smoke_test.py ray-traces a textured wall, a tilted floor and a box in front of the wall (exact depth for every view), with sources to the right, left, above and below the reference. Inlier ratio ($\lt$3% depth error) on all pixels and on the 3.4% of pixels the right-hand source cannot see:

The occlusion effect is already unmistakable: on pixels the stereo partner cannot see, going from 2 to 5 views raises the inlier ratio fourfold, while the score on all pixels moves by five points (the floor at grazing angle dominates the rest of the error). On this toy scene almost every partner-occluded pixel is visible in three other views, so mean and best-K tie; the real datasets, where only one or two sources may see a pixel, are where the aggregation rule should separate. The same test verifies the calibrated rectification used to run stereo networks inside MVS: a GT disparity round trip reproduces the reference depth on 99% of pixels for sources to the right, left, above and below.

10 · Reproduce

One script does everything — environments and the 11 model repositories, datasets, every benchmark, RESULTS.md and a self-contained report.html. It is idempotent: re-running it resumes where it stopped.

git clone -b multi-view-stereo https://github.com/nadurthi/computervision
cd computervision/multi-view-stereo
bash scripts/run_benchmark.sh quick /opt/mvs      # Ubuntu 22.04 + NVIDIA GPU; or: full
# subsets: METHODS="acmmp itermvs_blendedmvs" ONLY=mvs|stereo|latency|pointcloud RESET=colmap SKIP_SETUP=1

No GPU? scripts/make_synthetic_data.py plus SKIP_SETUP=1 DEVICE=cpu bash scripts/run_benchmark.sh smoke … runs the whole pipeline on the ray-traced scene in about five minutes.

On AWS, the launcher only wraps the same script with S3 syncing (datasets, weights and results are cached in a private bucket) and an auto-stop watchdog:

cd aws
./launch_mvs_ec2.sh launch                 # g6.2xlarge (L4), falls back to g5.2xlarge (A10G)
./launch_mvs_ec2.sh status                 # progress via SSM, no SSH
./launch_mvs_ec2.sh fetch ./mvs_results    # RESULTS.md, report.html, figures
./launch_mvs_ec2.sh rerun                  # same disk, resumes unfinished methods

The instance stops itself when the run ends, after 20 idle minutes, or after 8 hours. A quick run is about 3–5 hours on first setup (most of it downloading DTU depth maps) and well under that afterwards.

Datasets: DTU MVS (Aanæs et al.), ETH3D (Schöps et al.), Middlebury (Scharstein et al.), KITTI 2015 (Menze & Geiger), BlendedMVS (Yao et al.).
